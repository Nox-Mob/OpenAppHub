# Security review: OWASP Top 10 (2026-11-14)

A review of the whole suite (OpenAppHub, OpenCharterApp, OpenBoardApp, OpenLedgerApp, the docs site) against the [OWASP Top 10 (2021)](https://owasp.org/Top10/), done before the first production launch. The organization plans a SOC 2 audit later; each section notes the related SOC 2 Trust Services Criteria (CC = Common Criteria), so this document can be evidence for that audit.

Each finding is marked **Fixed** (in this round, with a test), **OK** (checked, nothing to change), or **Owner** (a setting or decision outside the code). The pre-production review before this one is [`review-notes.md`](review-notes.md) §6–9.

**How the suite is protected, in one paragraph.** Every app talks to Postgres (Supabase) through row-level security: each table says who may read and write each row, and the database enforces it whatever the client sends. Functions that need more power (`security definer`) check the caller first. There's no hand-written SQL from the browser: the Supabase client sends parameters, never SQL text. React escapes everything it renders. Server functions validate input with zod. Payment card data never touches the suite (Stripe Checkout).

## A02 Cryptographic failures

_SOC 2: CC6.1, CC6.7 (data in transit)._

| Finding                                                                                                                                                                             | Status                                                                                        |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Invitation tokens and email action-link tokens: only their SHA-256 hash is stored.                                                                                                  | OK                                                                                            |
| SMTP passwords (self-hosted) encrypted with AES-GCM (random IV, HKDF-derived key); Charter's Stripe keys encrypted with the gateway key. Unsubscribe links are HMAC-SHA-256 signed. | OK                                                                                            |
| Secrets live in Cloudflare and GitHub secrets, never in the repositories (`wrangler.jsonc` has only public values; a test fails if a `SECRET`/`SERVICE_ROLE`/`API_KEY` appears).    | OK                                                                                            |
| Data in transit: HTTPS everywhere (Cloudflare).                                                                                                                                     | OK                                                                                            |
| **No HSTS header**, so a first visit over plain HTTP could be downgraded.                                                                                                           | **Fixed**: `Strict-Transport-Security: max-age=63072000; includeSubDomains` in all four apps. |
| Data at rest: Supabase encrypts databases and backups (AES-256).                                                                                                                    | OK (Supabase)                                                                                 |

## A03 Injection (SQL, XSS, mail, CSV)

_SOC 2: CC8.1 (secure development)._

| Finding                                                                                                                                                                                                                                                                                                          | Status                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SQL injection.** The browser never sends SQL: the Supabase client sends parameters to PostgREST, which builds parameterized queries. Database functions that build SQL quote names with `%I`/`%L`; the only `%s` in executed SQL is a function name read from the registries, which only migrations can write. | OK                                                                                                                                                          |
| Registry function names (`email_jobs.fn`, trigger `scan_fn`, action `run_fn`, recipient `resolve_fn`…): defense in depth.                                                                                                                                                                                        | **Fixed**: each must be a plain `schema.function` (check constraints, core 0017; tested).                                                                   |
| **PostgREST filter injection.** One `.or()` filter took a value from the URL (Ledger's statement check ID); a crafted value could add conditions (RLS still kept it to the person's own books).                                                                                                                  | **Fixed**: only a UUID is accepted.                                                                                                                         |
| **XSS.** React escapes everything it renders; no `dangerouslySetInnerHTML` except the static theme script and the chart component's CSS.                                                                                                                                                                         | OK                                                                                                                                                          |
| Chart CSS is built from a config; today every config is static, but a key or color from data would go into a `<style>` tag.                                                                                                                                                                                      | **Fixed**: keys and colors are checked before they're written (all three apps).                                                                             |
| `javascript:` links: links from data go through `safePath()` (above), and the database refuses them.                                                                                                                                                                                                             | **Fixed**                                                                                                                                                   |
| **Emails**: every value in the HTML is escaped (`esc()`), link paths are joined to our own domain, header values have line breaks removed.                                                                                                                                                                       | OK                                                                                                                                                          |
| **SMTP command injection** (self-hosted): a recipient address with a line break could add a command or another recipient; the `<…>` extraction even picked out the injected address.                                                                                                                             | **Fixed**: `addressOf()` refuses anything but one plain address (tests in `shared/email/email.test.ts`), and the outbox refuses such addresses (core 0017). |
| **CSV formula injection** (`=HYPERLINK(…)` in a name): all exports (Charter roster and full export, Board, Ledger) prefix formula-looking cells.                                                                                                                                                                 | OK                                                                                                                                                          |
| **Input validation**: every server function with input validates it with zod; the database has its own checks (lengths, formats, enums).                                                                                                                                                                         | OK                                                                                                                                                          |
| Content Security Policy: `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, connections only to our Supabase project. **Inline scripts are allowed** (TanStack Start streams hydration scripts).                                                      | Accepted risk: the measures above stop untrusted content from reaching the page; moving to nonces is a framework change (tracked).                          |

## Owner actions from this review

1. Supabase (production): leaked-password protection on; minimum password length 8 or more; email confirmation on; redirect URLs limited to `openapphub.org` and the app domains.
2. GitHub: turn on Dependabot alerts and security updates in each repository.
3. Alerts: Cloudflare (Worker errors) and Supabase (auth failures, database health) to an operations email.
4. Decide on MFA for owners and admins (recommended before the SOC 2 audit).

## For the SOC 2 audit later

This review, `review-notes.md`, the CI history, the database tests for access rules (each repo's `db/tests`), and the audit logs are the evidence for CC6 (access), CC7 (operations and monitoring) and CC8 (change management). What SOC 2 will add that isn't code: written policies (access reviews, incident response, vendor management for Supabase, Cloudflare, Stripe and Resend), a yearly risk assessment, and evidence that they're followed.
